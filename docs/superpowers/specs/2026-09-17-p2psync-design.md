# p2pSync 总体设计文档

- 日期：2026-09-17
- 状态：待评审
- 关联文档：[P2P 发现与连接设计](./2026-09-17-p2p-discovery-design.md)

## 1. 项目目标

多人同时观看同一个网页视频并实时同步进度：

- **无需部署服务器**：任意两人之间直接建立 P2P 连接，同步数据不经第三方
- **一键分享**：房主生成一个地址，发送给其他人，对方点击即可加入房间
- **任意网页视频**：客户端内置浏览器打开视频网页（B站、YouTube 等），注入脚本控制视频

## 2. 总体架构

```
┌─────────────────── Electron 应用 ───────────────────┐
│  UI 壳（Vue3 + Vite + TypeScript）                   │
│  ├── 房间面板：创建/加入房间、成员列表、连接状态       │
│  └── 地址栏：输入/粘贴视频网址                        │
│                                                      │
│  WebContentsView（内置浏览器，加载视频网页）           │
│  └── 注入脚本：房主监听视频事件 / 成员执行同步指令      │
│                                                      │
│  core 同步引擎（与平台无关，可单元测试）               │
│  └── 消息协议 + 时钟校准 + 漂移补偿                   │
└──────────────────────┬───────────────────────────────┘
                       │ WebRTC DataChannel（P2P 全互联 mesh）
        ┌──────────────┼──────────────┐
     房主 A          成员 B          成员 C
        └─────── 公共信令（Trystero）────┘
```

### 2.1 进程与模块职责

| 模块 | 职责 |
|------|------|
| 主进程（electron/main） | 窗口管理、WebContentsView 生命周期、`p2psync://` 协议注册与唤起分发 |
| 预加载脚本（electron/preload） | 向渲染进程暴露受控 API（打开视频页、注入脚本、剪贴板） |
| 渲染进程 UI（src/） | 房间操作界面、成员列表、地址栏、状态提示 |
| 核心逻辑（core/） | 房间管理、同步消息协议、同步引擎、分享链接生成/解析；不依赖 Electron，可独立单元测试 |
| 注入脚本（inject/） | 房主端 monitor：监听视频 play/pause/seek 事件并上报；成员端 follower：接收指令控制视频 |

## 3. 技术选型

| 模块 | 选型 | 理由 |
|------|------|------|
| 桌面框架 | Electron | 内置完整 Chromium，可加载任意视频网页并通过 `executeJavaScript` 控制 `<video>` 元素 |
| UI | Vue3 + Vite + TypeScript | 轻量、类型安全 |
| P2P 通道 | WebRTC DataChannel | 浏览器原生 P2P 能力，连接建立后数据端到端加密直传 |
| 信令 | Trystero（nostr 策略为主） | 借用公共基础设施完成信令交换，本项目自身零部署、零账号；详见 P2P 专项文档 |
| NAT 穿透 | 公共 STUN（国内外混合列表） | 绝大多数家庭网络可打洞成功 |
| 分享地址 | 自定义协议 `p2psync://` | Electron `setAsDefaultProtocolClient` 注册，点击链接唤起应用 |

**关于"不需要服务器"的边界说明**：WebRTC 建连前必须通过某种途径交换连接信息（信令），Trystero 的做法是借用互联网上已有的免费公共服务（Nostr 中继、BT tracker 等）完成这一步，本项目自身不需要部署任何服务器；连接建立后所有同步数据走 P2P 直连。

## 4. 房间与分享地址

### 4.1 房间标识

- 房主创建房间时生成 `roomId`：`crypto.getRandomValues` 取 10 字节随机数，Base32 编码为 16 字符（约 80 bit 熵，防碰撞、防撞房）
- Trystero 命名空间：`appId = "p2psync-v1"`，与 `roomId` 共同派生信令 topic，避免与其他 Trystero 应用串台

### 4.2 分享地址

- 格式：`p2psync://join?room=<roomId>&url=<encodeURIComponent(视频页地址)>`
- 行为：对方点击链接 → 操作系统唤起 p2psync 应用 → 主进程解析参数 → 自动打开视频页并加入房间
- 兜底：UI 提供"复制房间信息"（roomId + 视频网址的文本），对方在应用内粘贴导入，用于自定义协议注册失败的场景

## 5. 同步机制

### 5.1 角色模型

- **房主权威模式**：房主是唯一时间权威，成员只跟随；成员本地的播放/暂停/拖动操作被注入脚本拦截（跟随模式）
- 房主与成员都通过同一注入脚本与 `<video>` 元素交互，差异只在事件方向：房主是"监听→广播"，成员是"接收→执行"

### 5.2 同步策略

- **事件推送**：房主的 play / pause / seek 操作立即广播给全员
- **周期校准**：房主每 2 秒广播一次心跳 `{position, playing, at}`；成员计算理论位置 `position + (playing ? now - at : 0)`，与本地实际播放位置比较：
  - 误差 > 0.35s → 直接 seek 到目标位置
  - 误差 ≤ 0.35s → 用 `playbackRate`（0.95~1.05 区间）微调追赶，避免画面跳动
- **新成员加入**：发送 `hello` → 房主回复全量 `state`（当前视频 URL、位置、播放状态）→ 成员导航到视频页并跳转到对应位置

### 5.3 消息协议

```ts
/**
 * 同步消息协议（DataChannel 上传输的应用层消息）
 * t: 消息类型；at: 房主侧发送时的墙钟时间戳（ms），用于成员端推算当前应处的播放位置
 */
type SyncMsg =
  /** 新成员加入后请求全量状态（仅成员→房主） */
  | { t: 'hello' }
  /** 全量状态/周期心跳（仅房主→全员） */
  | { t: 'state'; url: string; position: number; playing: boolean; at: number }
  /** 房主触发播放 */
  | { t: 'play'; position: number; at: number }
  /** 房主触发暂停 */
  | { t: 'pause'; position: number }
  /** 房主拖动进度 */
  | { t: 'seek'; position: number; playing: boolean; at: number }
```

## 6. 功能分期

### P0（第一期）

1. 地址栏输入/粘贴视频网址，内置浏览器打开
2. 创建房间（房主）/ 通过链接或房间码加入（成员）
3. 生成分享链接（`p2psync://`），一键复制
4. 同步 play / pause / seek / 周期校准
5. 成员列表 + 连接状态（连接中/已连接/失败原因）
6. 成员端跟随模式（拦截本地播放控制）

### P1（后续迭代）

- 文字聊天（DataChannel 上顺带实现）
- iframe 内嵌视频站点适配
- TURN 中继兜底（应对对称 NAT）
- 权限控制（谁可控制播放、多人房间房主迁移）

```
p2pSync/
├── electron/              # 主进程与预加载脚本
│   ├── main.ts            # 入口：窗口、WebContentsView、协议注册
│   └── preload.ts         # 渲染进程受控 API 桥
├── src/                   # 渲染进程 UI（Vue3）
│   ├── App.vue
│   └── views/             # 房间面板、成员列表、地址栏
├── core/                  # 与平台无关的核心逻辑（可单测）
│   ├── room.ts            # 房间管理（Trystero 封装：创建/加入/离开/成员事件）
│   ├── protocol.ts        # SyncMsg 类型定义与编解码
│   ├── syncEngine.ts      # 同步引擎：事件分发、周期校准、漂移补偿
│   └── shareLink.ts       # 分享链接生成/解析、roomId 生成
├── inject/                # 注入到视频页的脚本
│   ├── monitor.ts         # 房主端：监听视频事件并回调
│   └── follower.ts        # 成员端：执行同步指令、拦截本地操作
└── docs/
```

## 8. 风险与边界

| 风险 | 处理方式 |
|------|----------|
| 双方均为对称 NAT，STUN 打洞失败 | MVP 检测 `failed` 状态并向用户提示原因；TURN 列入 P1 |
| 视频位于 iframe 内的站点 | P0 仅支持主页面直出 `<video>` 的站点（B站、YouTube 等），iframe 站点 P1 适配 |
| DRM 加密视频（爱奇艺/腾讯部分内容） | Widevine 内容技术上无法注入控制，明确声明不支持 |
| 公共信令节点偶发不可达 | Trystero nostr 策略配置多个中继并行；详见 P2P 专项文档 |
| 国内网络环境下部分公共服务不可达 | STUN/信令节点均采用国内外混合列表，详见 P2P 专项文档 |
| 网站自动暂停逻辑（如切换标签页暂停） | 注入脚本在成员端拦截并覆盖网站的暂停行为 |

## 9. 测试策略

- **core/ 单元测试**：同步引擎的误差计算、消息编解码、链接生成/解析（Vitest）
- **注入脚本**：在本地测试页（含 `<video>` 的静态 HTML）上验证监听与控制
- **双实例联调**：本机同时运行两个应用实例（不同 userData 目录）模拟房主与成员
- **真实网络**：手机热点 + 家庭宽带跨网络验证打洞成功率
